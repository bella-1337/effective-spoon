LiteLLM Development Stack

LiteLLM owns client policy and uses remote D3-mini only for coding-tier decisions.

Request path

  • • Client -> Traefik -> LiteLLM
  • • D3 classifies coding effort
  • • LiteLLM dispatches the completion

Data and models

  • • BGE-M3 remains local
  • • Qdrant cache is opt-in
  • • PostgreSQL stores gateway state

Security boundary

  • • LiteLLM authenticates clients
  • • D3 uses separate bearer auth
  • • Remote traffic requires verified TLS

Remote D3-mini is separately operated and firewall-restricted to the LiteLLM host.
