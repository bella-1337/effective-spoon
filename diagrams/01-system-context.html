LiteLLM stack — system context

Who calls the stack, what runs inside the Docker host, and which services live outside it

Clients

  • • Browsers, SDKs, and agents reach the stack only through Traefik over HTTPS
  • • API clients authenticate to LiteLLM with a virtual key or the master key
  • • Operators use OpenSearch Dashboards, plus Grafana or Langfuse when enabled

Inside the stack

  • • LiteLLM is the single gateway for models, search, MCP tools, and guardrails
  • • Presidio, SearXNG, Xberg, PostgreSQL, and telemetry stay on internal networks
  • • Every container log, metric, and trace lands in OpenSearch by default

Outside the stack

  • • OpenAI serves completions; a separate GPU host runs D3-mini and dev BGE-M3 embeddings behind one TLS proxy trusted through its mkcert CA
  • • SearXNG scrapes public engines — review their terms of use
  • • Xberg reaches only allowlisted sites through the Squid egress proxy
