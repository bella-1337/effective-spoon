Xberg MCP extraction sandbox

LiteLLM is the authentication boundary; Xberg fetches remote documents only through an allowlisting proxy

Request path

  • • Clients call /mcp-rest/tools/call on LiteLLM, never Xberg directly
  • • Only extract, detect_mime_type, get_version, and list_formats are exposed
  • • Explicit injection phrases in tool results are redacted before return

Sandbox

  • • Xberg has no route to the internal network or the Internet
  • • Local paths and file:// URIs are disabled; only uploads and allowlisted URLs
  • • In dev, extraction results can feed opt-in pgvector auto-indexing

Egress control

  • • Squid allows HTTPS CONNECT to allowlisted hosts only and denies private ranges
  • • xberg-dns answers NXDOMAIN for every unlisted name, so lookups cannot exfiltrate data
  • • Keep the proxy, DNS, and Xberg allowlists aligned; grant MCP access only to trusted keys
