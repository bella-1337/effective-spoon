Xberg MCP extraction sandbox

LiteLLM is the authentication boundary; Xberg fetches remote documents only through an allowlisting proxy

Request path

  • • Clients call /mcp-rest/tools/call on LiteLLM, never Xberg directly
  • • Only extract, detect_mime_type, get_version, and list_formats are exposed
  • • Cache mutation and warming tools stay hidden

Sandbox

  • • Xberg has no route to the internal network or the Internet
  • • It has no published host port
  • • In dev, extraction results can feed opt-in pgvector auto-indexing

Egress control

  • • Squid denies private, loopback, link-local, and unlisted hosts
  • • Review every change to security/xberg-egress-allowlist.txt
  • • Xberg is a server-side fetcher — grant MCP access only to trusted keys
