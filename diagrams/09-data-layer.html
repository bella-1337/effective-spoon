Data layer, readers, and backups

Which service owns each database, who reads it with which role, and where backups go

Owners

  • • Each LiteLLM profile has its own database on one PostgreSQL
  • • pgvector runs in a separate PostgreSQL 16 instance
  • • postgres-init creates litellm_dev on a fresh volume

Readers

  • • The bridge reads with opensearch_ro; Grafana with grafana_ro
  • • Prompts, responses, and key hashes are never copied out
  • • Exporters expose database health to Prometheus

Backups

  • • Custom-format dumps validated by pg_restore
  • • Partial backups never advance the last-success metric
  • • Replicate off-host; a local backup does not survive host loss
