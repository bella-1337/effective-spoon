Development model plane — cache, RAG, and local embeddings

Dev-only services that give LiteLLM a semantic cache, a pgvector knowledge store, and local BGE-M3 embeddings

Semantic cache

  • • Opt-in per request with cache.use-cache
  • • Hit when cosine similarity is at least 0.92, scoped per end user
  • • Qdrant runs on tmpfs, so recreating it deletes every entry

Knowledge store

  • • sme-knowledge lives in vector-postgres (1,024-dim HNSW)
  • • Search goes through BerriAI's litellm-pgvector connector
  • • Opt-in Xberg auto-indexing anonymizes chunks with Presidio first

Scope

  • • Qdrant, BGE-M3, and the connector run only in the dev profile
  • • Production lists no vector store and no semantic cache
  • • Promote capabilities through the dev-to-prod register
